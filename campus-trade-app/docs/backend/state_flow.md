# 校园二手交易平台状态流转说明

## 1. 商品状态
- `待审核`
  - 用户发布商品后的初始状态
- `上架`
  - 管理员审核通过后可被前台搜索和详情页展示
- `交易中`
  - 商品存在进行中的订单时，前台展示层会显示为 `交易中`
- `下架`
  - 卖家主动下架、管理员违规下架、用户被禁用后自动下架
- `驳回`
  - 管理员审核不通过

## 2. 订单状态
- `待确认`
  - 买家在聊天页点击购买后生成
- `已确认`
  - 卖家确认订单后进入，可继续付款
- `进行中`
  - 买家完成付款后进入
- `已完成`
  - 买卖双方任一方完成收口后进入最终态
- `已取消`
  - 买卖双方主动取消
- `已拒绝`
  - 卖家拒绝订单

## 3. 支付状态
- `未支付`
  - 新建订单默认值
- `待支付`
  - 卖家确认订单后进入
- `已支付`
  - 买家完成支付后进入

## 4. 系统通知触发点
- 商品提交审核
- 商品审核通过
- 商品审核驳回
- 管理员违规下架商品
- 买家创建订单
- 卖家确认订单
- 卖家拒绝订单
- 买家付款成功
- 订单取消
- 订单完成

## 5. 数据落库原则
- MySQL 模式下：
  - 用户认证读写：`ct_user`
  - 商品：`ct_listing`、`ct_listing_image`、`ct_listing_tag`
  - 收藏：`ct_favorite`
  - 审核记录：`ct_listing_review`
  - 订单：`ct_order`
  - 订单日志：`ct_order_status_log`
  - 会话：`ct_conversation`
  - 消息：`ct_message`
  - 通知：`ct_notification`
- `app_state`
  - 仅保留为 JSON 驱动和首轮 MySQL 回填来源
  - 不再作为 MySQL 运行期业务读写源

## 6. 前端关键流程
- `我想要`
  - 创建或复用会话
  - 跳转消息页
  - 在聊天中再创建订单
- `付款`
  - 从订单详情页或相关入口进入
  - 选择支付方式后变更订单状态与支付状态
- `提醒`
  - 统一读取未读聊天、通知和订单相关提醒
  - 桌面端支持悬停预览，点击进入消息中心

## 7. 管理端治理流程
- 审核商品：
  - 通过：商品上架，卖家收到通知
  - 驳回：记录原因，卖家收到通知
- 违规处理：
  - 管理员输入违规原因
  - 商品强制下架
  - 卖家收到违规下架通知
